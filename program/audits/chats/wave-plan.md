# Chats wave plan (wave 3∥: Chats / HQ)

Gate A, 2026-10-01. Inputs: two code reads (design system; UX, i18n and accessibility), the baseline sweep and dead-end run (2026-09-30), and the decisions D-017, D-018, D-020, D-043 and D-046. The issue log is [issues.csv](issues.csv): 44 issues — 7 S1, 24 S2, 13 S3.

## What this wave is, and isn't

- **Is:** Chats on the OrgTik brand through the token bridge (D-020), in five languages and both themes. The suite session made real: the one-time code, the suite user as "me", sign-out that signs out, and View as read-only (D-017). The S1 flow fixes (attachments, leave vs end, navigation at every width, search on phones, guest links with a secret). The library's primitives replace the home-grown ones. Chats is the suite's chat from now on (D-018).
- **Isn't:** a new visual world for the office floor. The floor, furniture and daylight keep their own HQ tokens and get dark values; only their colours move. A real-time backend: the simulator stays, and what needs a server (guest links across browsers, the guest secret check) is written as a contract.
- **Stays:** the four accent presets, as per-person overrides of the brand (D-046). With no preset chosen, the accent is the OrgTik brand.
- **Repo:** `somion-hq`, branch `wave3/chats` from `local-dev/suite-integration` (459b478). Not pushed (D-044). Tasks runs in a parallel session (D-043); the two only meet in `@orgtik/ui` and SOS's `CODE_APPS`.

## Decisions taken inside the wave (reversible, by the design owner's earlier choices)

- **Presence "focus" moves from violet to teal**, at least 30° away from the brand, the presets and "in a meeting" blue. Every status keeps its icon and label, so hue never carries the meaning alone (CVD-safe).
- **Language:** Chats keeps its addresses (no `/ar/…` prefix, so guest and message links stay language-free) and reads the suite's `NEXT_LOCALE` cookie, like SOS (D-033). The pseudo-locales stay as a development-only QA toggle.
- **t() keeps its signature** `t(key, default, vars)`, so 1,135 call sites don't change. It now reads the active catalog first; the English default becomes `messages/en.json`, generated by an extractor and checked for drift.
- **Leaving a call is the default.** "End for everyone" is a separate, host-only action behind a ConfirmDialog that states the impact.

## Order

1. **Foundations** (FS-CHT-1) and the **bridge with dark mode** (FS-CHT-2).
2. **Languages** (FS-CHT-3): extractor and en catalog first, then ar, de, fr, it.
3. **Suite session** (FS-CHT-4), with `hq` added to SOS's `CODE_APPS`.
4. **Shell** (FS-CHT-5).
5. **Chat** (FS-CHT-6), then **meetings and calls** (FS-CHT-7), then the **office floor** (FS-CHT-8).
6. **Primitives** (FS-CHT-9), screen by screen, alongside 5.
7. **Cleanup** (FS-CHT-10). Then the flows run in en and ar, VS-1 runs on every route, and the issues are closed.

## Golden flows (to become `flows/chats.mjs`, quiet mode on)

- **C0 Open from the suite:** SOS → Chats from the rail → signed in as Mona, no token in history; Arabic flips the page to RTL.
- **C1 Send a message with a file:** #design → attach → Send → the message shows the file.
- **C2 Start a conversation:** New message → two people → Start group → the same two again → the same group opens.
- **C3 Meet now and a guest:** Meet now → Join now → Invite people → copy the link → a guest (second page, same browser) joins by the secret link → Reset link → the old link is refused.
- **C4 Leave or end:** Leave → the meeting keeps running for the guest; End for everyone (confirmed) → the guest sees "This meeting has ended".
- **C5 Status:** Set your status → Focus → note saved → the dot is teal with its label.
- **C6 Search:** at 1440 and 390, search "launch" → results → open one → Back returns to Chat.
- **C7 View as:** SOS View as Aya → Chats → banner says read-only → sending is refused with the reason.
