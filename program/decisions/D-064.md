# D-064: platform-priced website offers keep four terms and existing greater-of savings

| | |
|---|---|
| Status | **Accepted** (2026-10-07, revised roadmap) |
| Owner | Platform pricing / website integration owner |
| Decided by / approver | Yossef |
| Refines | D-058, D-059; amendment A11 |

## Context and options

D-058 makes the platform the price authority. Replacing website offers with monthly/yearly subscription rules would change the approved purchasing experience. Keeping paid totals in the browser would let client receipts create invoices without platform verification. The approved choice moves existing website arithmetic into the platform while preserving presentation.

## Decision

Website offers keep **1/3/6/12-month** terms and existing renewal choices. Duration savings are **0/5/10/15%** for those terms. Distinct-item savings are **0/5/10/15%** for **1/2/3–4/5+** distinct items. Use the greater saving; duration wins ties. Round once per full-period line, using the resolved currency's precision. Preserve existing item identity/count semantics rather than treating seats or quantities as extra distinct items.

Keep this offer policy separate from subscription checkout's **bundle → coupon → proration → tax** policy. Resolve regional base prices in the platform. Register service offers individually with their distinct identities and fulfilment mappings; website management creates a managed-service request under D-059, never internal CMS access.

Bring the minimum public catalog/offer quote and simulated checkout adapter into R0. The platform creates the simulated paid order before account linking, stores resolved region/pricing policy, and determines the invoice amounts. Browser totals and receipt state cannot create a paid invoice. Authenticated linking is idempotent and cannot change an immutable paid order's currency.

## Consequences and acceptance

- Website catalogs retain presentation; existing terms, renewal choices, cart/back navigation and visual identity stay intact.
- Test all four terms, all item-count bands, greater-of/tie cases, currency precision, altered client totals, failed payment and repeated linking.
- Compare actual quote/checkout/invoice endpoints, not just a copy of the helper arithmetic. Document the permitted wording, pricing and mock-region display differences in website parity evidence.
- Existing accounts and historical invoices are preserved. Live payment-provider integration remains deferred under D-063.
