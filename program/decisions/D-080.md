# D-080: customer administration inside each tool

Status: accepted scope, 2026-10-09. Implementation pending P2–P4.

## Decision

`ToolAdminLayout` has eight shared sections: overview (plan/seats/usage/billing), members/seats, roles, settings, connections, import/export, audit and billing. Workspace owners/admins and explicitly authorized tool admins may enter; administration still requires that tool's current subscription/access. Billing recovery links are owner actions; other users request help/access.

Settings are domain-specific: Tasks statuses/labels/templates/fields; Files sharing/versions/storage; Chats channels/retention/guests/calls; HR departments/leave/holidays/payroll/documents; CRM pipeline/fields/routing/quotes; Marketing brands/senders/consent/UTM. Retain the current account as membership/seat authority.

`workspace-commands.js` currently permits role changes for Tasks and Files only. Extend its role catalog through the bounded D-075 adapter allowance, reusing `TOOL_DEFINITIONS`, current membership and guest limits. A tool admin can administer only its tool, cannot become workspace owner or gain OrgTik staff permission, and cannot bypass assigned seats or read-only state.

Acceptance is an ordinary-route owner/admin flow, a non-admin refusal, a seat-limit/request state, a billing state and localized/responsive captures for each applicable tool. Export/import remains within packaged-file/mock constraints; real providers stay deferred.
