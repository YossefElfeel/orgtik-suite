# D-072: canonical, versioned whiteboards in Files

Status: implementation choice for approved R2/D-066, 2026-10-08; merged through PR19 into main `1d8c5df` after CI37732109610 passed. Hosted roadmap acceptance remains open.

Files owns immutable canonical vector/text scene versions. Chats keeps the associated board index and current minimum Files reference, rather than a second mutable drawing. Saving a changed scene appends a content version and advances the Chats index in one checkpoint; an existing Tasks/Chats reference keeps its original bytes. Explicit saves use the original operation key and base version. Current authority is checked before receipt recovery; stale new saves return a conflict, while exact prior saves return their original saved reference alongside the current head.

Read access intersects Files permissions with current Chats assignment and the standalone author, conversation member or canonical saved-meeting participant. Neither a workspace owner nor an administrator bypasses a private conversation. Native Files metadata/download/ZIP and recursive folder mutations apply the same source gate. Offboarding transfers only to an association-eligible successor and otherwise archives both records without adding private membership.

Canonical scenes accept bounded local vectors, text and frames:256KiB UTF8,1000 elements,20000 points and100000 text characters. Images, binary files, embeds and external links are excluded. Transient selection/view state and volatile reconciliation counters do not create a content version. A packaged SVG is a clearly labelled sample preview; it never claims to depict the saved scene. Structured public sharing remains unsupported, including folder share traversal; ordinary asset sharing remains intact.

The existing Excalidraw component remains the editor. It uses explicit dirty/saving/saved, read-only, historical-version, conflict and original-attempt recovery states. New workspaces stay empty until a user creates a board. Persistent meeting creation, generic file-version editing/name clashes, comments and live integrations remain separate work. All15 hosted release journeys remain open while deployment is paused.
