# D-014: LocalizedField: tabs with a completeness badge per language

| | |
|---|---|
| Status | **Accepted** (2026-10-01) |
| Owner | Claude (UX) |
| Approver | PM (packet 01, Q-007) |
| Needed by | P1 |
| Evidence still pending | PM answer on which languages are required per surface |

## Context

The spec shows Arabic and English inputs side by side. The suite has five languages (D-001), and five side-by-side inputs don't fit. Editors also need to see at a glance which translations are missing.

## Options

| Option | For | Against |
|---|---|---|
| Side by side | Direct comparison | Only fits two languages |
| All five stacked | Everything visible | Very long forms |
| **Tabs with a completeness badge** (proposal) | Fits any number of languages; shows what's missing | One language visible at a time |
| Translations only on a separate screen | Clean forms | Editors lose context |

## Proposal

- **Two languages:** side by side, as the spec shows.
- **Three to five:** tabs. Each tab has a completeness badge.
- On a validation error, focus moves to the first language with a problem.
- **Required languages:**
  - SaaS content: English and Arabic are required, and German, French and Italian fall back in the UI until translated.
  - Website content: every public language must be ready before publishing (plan, phase 2).


## Decision (2026-10-01)

Accepted by Yossef (ahead of the PM's answer to Q-007): LocalizedField: tabs with a completeness badge for 5 languages (EN and AR required; the others fall back until translated), replacing the spec's side-by-side AR/EN inputs.

The PM packet still asks the question; if the PM answers differently, this decision reopens.
