# D-068: one authoritative workspace and session boundary

Status: accepted implementation choice for the approved R1 roadmap,2026-10-07.

Customer sessions carry one selected workspace and destination audience. Current membership, explicit tool roles, assigned seats and subscription state determine access; global identity roles never grant customer workspace privileges. OrgTik ADM/WM permissions are separate and require current internal membership. A guest cannot override its restricted role with an administrative tool grant.

Owned CommonJS graphs and versioned snapshots isolate Tasks, Files, HR, CRM, Marketing and Chats. New workspaces begin empty; named fixtures stay independent. Historical accepted tool writes migrate privately to the OrgTik fixture without using current HTTP authorization or changing paid financial facts. Public Files grants select their own workspace before resource lookup.

Sessions are signed, persisted and revocable. Refresh rotates; reuse revokes its family; handoff is destination-bound and consumed once. Offboarding increments the affected membership access epoch, so rehire cannot reactivate old session families and other workspaces remain usable. Browser credentials and caches belong to the tab's verified context; cookies provide routing compatibility only.

Account and workspace effects commit together. Current security authority is rechecked before domain persistence; the domain CAS fences concurrent membership changes. Failed persistence returns failure. These are hosted mock foundations; live identity providers and functional mock2FA retain their later roadmap scope.
