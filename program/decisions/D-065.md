# D-065: automatic mock visitor region, Switzerland fallback and controlled test overrides

| | |
|---|---|

| Decided by / approver | Yossef |

## Context and options

Regional platform pricing needs visitor context before sign-in. A new country selector would change the approved website. Live geolocation would add an external integration. The approved prototype uses automatic mock detection and a deterministic fallback.

## Decision

Use automatic **mock** region detection for visitors. When detection is absent or unusable, resolve **Switzerland (CH)**. Provide controlled validated overrides for local/isolated preview tests so CH/EU/GCC and failure scenarios are repeatable. Do not add a new public country selector or require a live geolocation provider.

For signed-in customers, the selected workspace's billing region and currency are authoritative. Visitor hints/test controls cannot override that workspace billing context. Resolve regional base prices, tax display and supported payment routing server-side; retain the resolved region with the order as D-064 requires.

## Consequences and acceptance

- Preserve website visual identity and document any small mock-region display wording added for clarity.
- Cover detected-region behavior, absent/invalid detection, CH fallback, permitted test overrides, and signed-in workspace precedence in quote/checkout regressions.
- Keep overrides scoped to controlled prototype testing and prevent them from mutating immutable paid-order currency.
- Real geolocation and public Arabic website launch remain deferred. This policy adds no live provider or production billing change.
