## Decision (2026-09-30)

Accepted as proposed: Base UI is the one primitive layer; dates use React Aria's calendar inside the library's Base UI popover.

## Context

The apps use three primitive libraries:

| Library | Apps |
|---|---|
| Radix | sos (11 packages), tasks (17), files, marketing (6), content (15), hr |
| Base UI | sales (1.6), hr (1.3) |
| React Aria Components | hr (1.16) |

HR carries all three. Chats (HQ) has its own components.

The library needs controls the specs call for: number, money and percent fields; a combobox with multiple selection; a meter; field and form validation; a drawer; a one-time-code field. All of them need full RTL. Overlays from two libraries nested inside each other fight over focus and dismissal.

## Options

| Option | For | Against |
|---|---|---|
| A. Radix everywhere | Most code uses it today | No number field, no multi-select combobox; those need extra packages, each with its own RTL and styling rules |
| **B. Base UI everywhere** (proposal) | Covers most of the spec's controls in one library. Sales, the only app running Arabic RTL today, already uses it. | The six Radix apps migrate their overlays |
| C. React Aria everywhere | Strongest accessibility and locale formatting | A rewrite of every component, with a heavier API for app developers |
| D. Keep all three behind the library API | No migration | The nested-overlay bugs stay, and three libraries' worth of RTL behaviour needs testing |

## Proposal

- **Base UI** is the primitive layer for everything, hidden behind a shadcn-like `@orgtik/ui` API.
- **React Aria Components** are used only for date and time pickers, because of calendar systems, locale formats and RTL.
- Apps can't import primitives directly; a lint rule enforces it (`prefer-orgtik-imports`).
- Radix apps get a deprecated `asChild` shim and an `as-child-to-render` codemod, so the ~1,964 existing imports keep working on day one.
- **Rule:** never nest overlays from different primitive libraries. A screen's overlay family (dialog, popover, menu, tooltip) migrates together.

## Consequences

- HR drops Radix in its wave, and the six Radix apps migrate overlay families one pull request at a time.
- The library team maintains one set of RTL and accessibility tests.

## Revisit if

- The spike finds an RTL keyboard gap with no fix path.
- A control the specs need (drawer, one-time code) is missing and can't be built on Base UI's parts.
