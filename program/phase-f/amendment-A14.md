# A14 — staged leave and approved availability

2026-10-08 · reviewed working package based on merged PR15; package CI and hosted acceptance pending.

J7 exposed three implementation gaps: a no-file HR request still submitted multipart to the deferred-upload path; the workspace decision helper bypassed HR's manager/HR stages; and no consuming calendar displayed approved availability. This package uses JSON commands with original operation keys, verified current-role/team decisions, the existing detailed serializer and current server capabilities. Missing manager approval is displayed as not required. New binary uploads remain deferred; historical packaged attachment display is preserved.

Tasks and Chats read the selected workspace's canonical approved HR records through their own authenticated tool APIs. The projection intersects active employment, account, membership and tool assignment. It exposes only person/date/time availability with the workspace timezone, and no medical category, notes, attachments or HR request links. Guests receive no coworker projection. Calendar rows are read-only and reset/rejection removes them through polling. Full-day bounds use the first valid instant of each civil day, including Cairo's missing-midnight transition; explicit partial-time gaps remain invalid.

The dispatcher now preserves the original HTTP target and rejects remote overrides/CRLF; invalid capabilities return403 without crashing or falling back to a legacy app. Binary/cookie/redirect behavior remains covered. This prerequisite repair belongs to the affected flow package and changes no deployment setup.
