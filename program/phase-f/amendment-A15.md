# A15 — trusted deadlines and durable staff revocation

2026-10-08 · reviewed working source based on merged PR16; package CI and full release acceptance pending.

Deadline transitions now run before the user rollback baseline under the existing realm journal lock. Offboarding/custody commits first, then billing/time transitions commit separately, and the caller is prepared against the resulting current state. An old owner's refusal cannot undo a due departure, and a later billing persistence failure cannot retain departed access. Neither phase accepts a client actor, payment total or clock value; both journal complete `workspace-v1` checkpoints and replay their committed state.

The coordinator observes the existing server clock, uses pure completed-marker selectors, and avoids creating operation receipts on every unchanged poll. It retries one system CAS conflict after synchronization and canonical account/app reacquisition; a second conflict returns failure, and storage failures do not retry. Rebuilding no longer leaves old identity, account snapshot or app/store closures in the next user transaction. A regression commits a competing checkpoint, then proves same-request registration and its workspace survive cold restart.

Scoped lifecycle advancement fixes the reproduced cross-workspace downgrade/renewal loss. Global price publication still processes all affected workspaces once. The debt gate and existing unpaid-invoice lookup use the same canonical boundary, preserving issued invoice amounts/currencies. Renewals, retries1/3/5,7-day grace, day37 expiry and scheduled quantities reuse the existing reducers. No persistent clock is advanced by the coordinator; health/status and immutable public assets remain smoke surfaces.

Date-only offboarding ends at the first valid instant of the following workspace day, including Cairo's skipped midnight. OrgTik's last qualified super-admin requires an already active replacement before scheduling; a peer already due to leave is not a valid replacement. Late failure records a recovery incident while still ending departed membership and authority. All internal departures persist a revocation marker and increment a staff access epoch once. Stored roles, credentials and independent customer workspaces remain history/current data as appropriate; ordinary HR rehire does not restore staff authority. Staff/view-as families bind the epoch, preventing old sessions from reviving after a deliberate future reappointment. Corrupt authority dictionaries fail closed.

Evidence:372 checks in the retained mock chain,20 consuming-app type/catalog tasks and24 tooling/artifact guards. Nine signed HTTP scenarios include actual two-process CAS, all-six-tool grace/read-only/recovery, custody transfer/archive and cold restart, rollback, staff replacement loss and preserved other-workspace access. The34 billing/lifecycle,22 HR and24 session cases are overlapping subsets, not extra totals. [The69-check UI report](../audits/r1-due/hr/README.md) distinguishes actual options from controlled recovery projection and records12 captures with matching source hashes.

Full R1 integrated acceptance and all15 isolated hosted journeys remain open, as do deliberate staff reappointment/recovery surfaces and remaining R2–R4 work. The72 original commitments remain retained. Vercel remains disabled; production data and its shared clock were not reset or advanced.
